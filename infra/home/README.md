# جهازك كسيرفر رئيسي، وRender احتياطي تلقائي

<div dir="rtl">

عندما يكون جهازك شغّالاً ومتصلاً، يخدم هو كل المستخدمين (أقوى بكثير من خادم Render المجاني).
عندما يُطفأ أو ينقطع، يتولى Render خلال أقل من ثانية، بنفس العنوان
`https://deepcode-2sfl.onrender.com`، وبدون أي تحديث للتطبيق.

## كيف يعمل

</div>

```
المستخدم ──► deepcode-2sfl.onrender.com (Render)
                 │  يفحص جهازك كل 5 ثوانٍ
                 ├─ جهازك سليم  ──► Tailscale Funnel (https) ──► جهازك (Docker)
                 └─ جهازك مطفأ  ──► نسخة Render نفسها
            الاثنان يستخدمان نفس قاعدة البيانات وRedis (نفس المستخدمين والرصيد)
```

<div dir="rtl">

- جهازك لا يفتح أي منفذ في الراوتر، وعنوانك (IP) لا يظهر.
- جهازك **يرفض أي طلب** لا يحمل كلمة سر سرية يضيفها خادم Render فقط (يرد 404).
- كل رد فيه الترويسة `X-DeepCode-Server: home` أو `cloud` لتعرف من خدمه.

## الإعداد (مرة واحدة)

1. **ثبّت Tailscale وسجّل الدخول** (حساب مجاني):

</div>

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

<div dir="rtl">

2. **شغّل الخادم على جهازك** (يبني نفس صورة الإنتاج ويشغّلها، ويُنشئ `home.env` بكلمة السر):

</div>

```bash
cd "infra/home" && ./setup.sh
```

<div dir="rtl">

3. **افتح النفق العام** (مرة واحدة، يبقى بعد إعادة التشغيل):

</div>

```bash
sudo tailscale funnel --bg 10000
```

<div dir="rtl">

   إذا طلب تفعيل Funnel في حسابك، افتح الرابط الذي يظهر ووافق.

4. **في Render** (الخدمة deepcode ← Environment) أضف قيمة واحدة ثم انشر:
   - `HOME_ORIGIN` = اسم جهازك في Tailscale (يطبعه `./setup.sh`، مثل `alsrkal.tail1234.ts.net`)

   كلمة السر بين Render وجهازك تُشتق تلقائياً من `GATEWAY_INTERNAL_TOKEN` الموجود عند الطرفين.

بعد النشر سجل Render يكتب `proxy mode: front`.

## الاستخدام اليومي

| الأمر | ماذا يفعل |
| --- | --- |
| `./setup.sh` | تشغيل الخادم (يعمل تلقائياً بعد إعادة تشغيل الجهاز) |
| `./setup.sh update` | تحديث جهازك لآخر كود (افعلها مع كل نشرة على Render) |
| `./setup.sh stop` | إيقاف جهازك؛ Render يخدم الجميع |

## ملاحظات مهمة

- **حدّث الاثنين معاً:** بعد كل نشرة على Render شغّل `./setup.sh update` حتى يبقى الجهاز وRender على نفس الإصدار.
- الطلب الذي يكون قيد التنفيذ لحظة إطفاء الجهاز قد يفشل مرة واحدة (التطبيق يعيده تلقائياً)، وكل ما بعده يذهب لـ Render.
- عند رجوع الجهاز، تعود الحركة إليه خلال ~10 ثوانٍ بعد جاهزيته.
- `home.env` و`../render/render.env` فيهما أسرار الإنتاج: لا تشاركهما ولا ترفعهما (هما في `.gitignore`).
- لإلغاء الميزة: احذف `HOME_ORIGIN` من Render، فيعود يخدم كل شيء بنفسه.
